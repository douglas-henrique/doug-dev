# Code review

[Douglas Pereira](/pt)

## Revisa a mudança, não a pessoa

- Pergunta o porquê antes de pedir reescrita
- Nitpick vai por último, ou numa passada à parte
- Se você não bloquearia, não usa linguagem de bloqueio

## Velocidade também conta aqui

- PR parado por dias já nasceu velho
- Diff pequeno ganha review de verdade
- Diff gigante ganha um encoger de ombros e um approve

## Ensina no comentário

- Link para o padrão
- Mostra a versão que você mergearia
- Quem lê o fio depois não estava na sua cabeça

## Aprova quando está melhor

- Perfeito é como o trabalho morre no review
- Follow-up vira ticket se não for essa mudança
- Seu trabalho é pousar coisa boa, não ganhar a caixa de comentário
